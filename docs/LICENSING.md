# Licensing — can you sell this?

**Yes.** Every third-party component Sumcheck bundles is under a permissive
license that allows commercial use, modification, and redistribution inside a
closed-source, paid product. Nothing here is GPL, AGPL, LGPL, SSPL, or
source-available/"fair source". You own your own code and can license it however
you like.

What you *must* do is attribution: ship the license texts, keep the copyright
notices, and don't claim the upstream authors endorse you. `THIRD_PARTY_NOTICES.md`
(generated by `npm run notices`) satisfies this, and `scripts/package.mjs`
includes it in the uploaded package.

### The two dual-licensed components

Both offer a choice, and in both cases the permissive option is available to you
with no strings attached. The election is recorded in `scripts/fetch-vendor.mjs`
so it is documented in the build itself, not just here.

- **JSZip** is `MIT OR GPL-3.0-or-later`. Taking the MIT option is explicitly
  allowed by the project, and MIT imposes no copyleft. Do not describe your
  product as "GPL" anywhere; you are not using that grant.
- **DOMPurify** is `MPL-2.0 OR Apache-2.0`. Apache-2.0 is the cleaner choice for
  a closed product: MPL-2.0 is file-level copyleft, meaning *modified DOMPurify
  files* would have to be published. Sumcheck ships DOMPurify unmodified, so
  either option would work — but electing Apache-2.0 removes the question
  entirely, and means you stay compliant even if you later patch it.

### Apache-2.0 in particular

Apache-2.0 (pdf.js, Tesseract, Readability, the OCR language data) is the most
"demanding" license in the stack, and its demands are still light:

1. Include a copy of the license (done — `THIRD_PARTY_NOTICES.md`).
2. Keep existing copyright, patent, trademark and attribution notices (done —
   the vendored files are byte-for-byte upstream, including their headers).
3. If you modify a file, say so in that file. Sumcheck does not modify any
   vendored file; it only *calls* them. If you ever patch one, add a line to its
   header noting the change.
4. It grants you a patent license, and terminates that grant only if you sue an
   upstream contributor over patents. Ordinary commercial use is unaffected.

Apache-2.0 does **not** require you to open your source, share your changes, pay
royalties, or use a particular license for your own code.

### The SIL Open Font License (the bundled fonts)

The Liberation-family fonts inside pdf.js are OFL-1.1. Two practical rules:

- You may bundle and redistribute them in a commercial product. ✅
- You may not sell the font files *by themselves*, and if you modify them you
  must rename them. Sumcheck does neither.

If you'd rather avoid the OFL entirely, you can drop
`vendor/pdfjs/standard_fonts/` and remove `standardFontDataUrl` from
`pdfDocumentDefaults()` in `src/core/vendor.js`. The cost is worse fidelity on
PDFs that rely on the standard-14 fonts without embedding them. Keeping them is
the recommended default.

## Sumcheck's own licence — Apache 2.0

`src/`, `scripts/`, the UI, the layout heuristics, the conversion pipeline and
the validators are licensed under the **Apache License 2.0**, as of 17 August
2026. `LICENSE` is the verbatim licence text; `NOTICE` carries the attribution
Apache §4(d) asks downstream distributors to preserve. Both ship inside the
packaged extension, and `npm run check` fails the build if either is missing.

This replaces the "all rights reserved" default the repository carried while it
was private, and the instruction that used to sit here — *"replace it with your
EULA or commercial terms when you publish"* — has been executed the other way:
the repository is public and the code is open.

**What that grants.** Anyone may use, modify, distribute and sell Sumcheck or
work derived from it, including in closed-source products, provided they keep
the copyright and licence notices and state what they changed. Apache 2.0 also
carries an explicit patent grant, which is the main reason to prefer it over MIT
for something that ships a nontrivial pipeline.

**What it does not grant: the name.** Apache §6 withholds trademark rights, and
that is deliberate rather than incidental. A fork gets the code; it does not get
to call itself Sumcheck, use the Σ mark, or publish to the Chrome Web Store in a
way that implies it is this product. That is the same courtesy this project
extends to Mozilla and Tesseract below, applied to itself.

**Relicensing is one-way in practice.** Code released under Apache 2.0 stays
released; a future version can be licensed differently, but the versions already
published cannot be recalled. That is a consequence of publishing, not a defect,
and it was the owner's decision to make.

Third-party components are unaffected: they were already permissive, they keep
their own licences, and `THIRD_PARTY_NOTICES.md` remains the authority on which
is which.

Practical checklist before a release:

- [ ] `npm run notices` after any dependency change, and commit the result
- [ ] `THIRD_PARTY_NOTICES.md`, `LICENSE` and `NOTICE` are inside the uploaded
      package (`npm run package` does this; `npm run check` enforces it)
- [ ] Link to those notices from an "Open source licenses" item in the UI or
      your listing
- [ ] Don't use "Mozilla", "pdf.js", "Tesseract", "Adobe" or "Foxit" in your
      product name, icon, or marketing in a way that implies endorsement
- [ ] If you ever fork a vendored file, note the modification in its header —
      Apache §4(b) asks the same of anyone who forks Sumcheck

## What is deliberately *not* used

These would have been convenient but carry terms that conflict with selling a
closed-source product, or that add obligations you would have to manage:

- **Ghostscript** (AGPL unless you buy a commercial license) — for PDF work
- **`pdftohtml` / Poppler** (GPL) — for PDF work
- **LibreOffice headless** (MPL-2.0, plus a huge runtime you can't ship in an
  extension) — for Office formats
- **Any cloud OCR or conversion API** (Google Vision, AWS Textract, Adobe PDF
  Services) — recurring cost per user, and it breaks the on-device promise
  that is the product's main selling point
- **SheetJS Pro** — the community edition is Apache-2.0, but the distribution
  moved off npm and the split invites confusion. Sumcheck reads XLSX directly
  (`src/core/adapters/xlsx.js`, ~250 lines) instead.

## One thing that is not a licensing question

The Chrome Web Store requires a privacy disclosure. Sumcheck's answer is short and
strong: it makes **no network requests at runtime**, so no user data is collected
or transmitted. `npm run check` enforces this by scanning `src/` for runtime
`fetch()`/`import()` of remote URLs, and MV3's `content_security_policy` blocks
remote code regardless. Say exactly that in your listing — it is the most
valuable claim the product has, and it is verifiable.

The one deliberate exception is opt-in and user-initiated: "Convert linked file"
asks Chrome for permission to that specific site so the file can be downloaded
and converted. That is why `optional_host_permissions` exists in the manifest
rather than a blanket host permission.
